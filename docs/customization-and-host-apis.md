# iOS SDK customization and host APIs

This guide covers the public customization and host-integration surfaces in the Artemis iOS SDK. The UI is built with SwiftUI and can be hosted by either SwiftUI or UIKit. The UI module re-exports the socket SDK types, so an app can import `ArtemisUISDK` to use `AgentChatUI` and `AgentSDK`.

The SDK follows the same broad customization areas as the Android guide—branding, chat regions, text, templates, behavior, and host callbacks—but uses native iOS APIs. Use the Runtime widget theme for server-managed branding and the host APIs below for app-specific UI and integration.

## 1. Configure the SDK

Create an `SDKConfiguration` in Swift, load it from YAML/JSON, or let the chat UI load its bundled YAML resource.

### Programmatic configuration

```swift
import ArtemisUISDK

let configuration = SDKConfiguration(
    environment: "dev",
    connection: ConnectionConfig(
        projectId: "your-project-id",
        endpoint: "https://runtime.example.com",
        apiKey: "pk_your_public_key"
    ),
    channel: ChannelConfig(channelId: "your-channel-id"),
    theme: ThemeConfig(
        primaryColor: "#0066FF",
        textColor: "#1A1A1A",
        backgroundColor: "#FFFFFF",
        surfaceColor: "#F5F5F5",
        borderRadius: 16,
        fontFamily: "System",
        darkMode: false
    ),
    features: FeaturesConfig(
        enableRichContent: true,
        enableMarkdown: true,
        enableCarousel: true,
        enableForms: true,
        enableQuickReplies: true,
        enableFeedback: true,
        showAnsweredByAI: true
    ),
    localization: LocalizationConfig(
        defaultLocale: "en",
        fallbackLocale: "en",
        overrides: ["Answered by AI": "Generated by our assistant"]
    )
)
```

Supply the credential supported by your deployment in `ConnectionConfig`. It can use an API key, a bootstrap token, or a bootstrap-token provider. Configure the channel, user context, and environment for your Runtime deployment.

### YAML configuration

Add `sdk_configurations.yaml` to the app bundle. The root key must be `artemis_sdk`.

```yaml
artemis_sdk:
  environment: dev
  connection:
    project_id: "your-project-id"
    endpoint: "https://runtime.example.com"
    api_key: "pk_your_public_key"
  channel:
    channel_id: "your-channel-id"
  theme:
    primary_color: "#0066FF"
    text_color: "#1A1A1A"
    background_color: "#FFFFFF"
    surface_color: "#F5F5F5"
    border_radius: 16
    font_family: "System"
    dark_mode: false
  features:
    enable_rich_content: true
    enable_markdown: true
    enable_carousel: true
    enable_forms: true
    enable_quick_replies: true
    enable_feedback: true
    show_answered_by_ai: true
  localization:
    default_locale: en
    fallback_locale: en
    overrides:
      "Answered by AI": "Generated by our assistant"
```

Load a bundled file directly, or let `AgentChatUI` load the default resource:

```swift
let sdk = try AgentSDK.initialize(
    fromBundle: .main,
    resourceName: "sdk_configurations",
    resourceExtension: "yaml",
    environment: "dev"
)

// Or let the UI load sdk_configurations.yaml from the app bundle:
let chat = AgentChatUI.view(configuration: nil, environment: "dev")
```

For file-based configuration, `SDKConfigurationLoader.load(from:environment:environmentOverrideURL:)` merges an optional environment file such as `sdk_configurations.dev.yaml` over the base file. The YAML-string initializer does not load an environment override file.

### Configuration areas

The `SDKConfiguration` value groups connection settings with these supported configuration areas:

| Configuration | Supported settings |
| --- | --- |
| `channel` and `userContext` | Channel ID, channel name, deployment slug, user ID, and custom user attributes. |
| `websocket` | Reconnection enablement, retry count and delays, exponential backoff, transient retry policy, and idle disconnect behavior. |
| `chat` | Local message limit, history page size/count, typing indicator, thought/activity display, file upload, file size, and allowed file types. |
| `voice` | Voice enablement, mode, barge-in, voice activity detection, sample rate, and channel count. |
| `storage` | Message cache, offline queue, secure-storage key prefix, and cache lifetime. |
| `performance` | Low-power mode, reduced animations, image quality, history pagination, and avatar prefetching. |
| `accessibility` | Screen-reader setting, minimum touch target, high contrast, and haptics. |
| `theme` | Base colors, border radius, font family, dark-mode default, timestamp formats, and phone-number link behavior. |
| `features` | Rich content, Markdown, carousel, KPI cards, forms, quick replies, voice, file upload, feedback, activity updates, attachments, Contact Center, history, citations, and AI attribution. |
| `localization` | Default, supported, and fallback locales plus host-provided string overrides. |
| `security` | TLS enforcement, certificate validation, and optional certificate pinning. |
| `session` | Idle timeout, end-on-idle, stale-session refresh, and end-session-on-close behavior. |
| `attachments` | Maximum file size and allowed MIME types. A message can contain up to five files. |
| `contactCenter` | Optional SIP stack URL. |
| `debug` and `analytics` | Logging controls and analytics enablement/provider/event selection. |

YAML uses snake-case keys (for example, `enable_contact_center` and `message_timestamp_format`). Programmatic Swift configuration uses the corresponding camel-case initializer arguments.

## 2. Present the chat

### SwiftUI

```swift
NavigationStack {
    AgentChatUI.view(
        configuration: configuration,
        title: "Support"
    )
}
```

You can also apply presentation options through the `artemisChatOptions` view modifier:

```swift
NavigationStack {
    AgentChatUI.view(configuration: configuration)
        .artemisChatOptions(ChatUIOptions(appearance: .system))
}
```

An explicit `uiOptions` argument to `AgentChatUI.view` takes precedence over options supplied through the environment modifier.

### UIKit

Push chat onto an existing navigation stack:

```swift
let opened = AgentChatUI.show(
    in: self,
    configuration: configuration,
    title: "Support",
    hidesBottomBarWhenPushed: true,
    animated: true
)
```

The method returns `false` if there is no navigation controller or chat is already at the top. To present chat modally:

```swift
AgentChatUI.present(
    from: self,
    configuration: configuration,
    title: "Support"
)
```

The modal presentation is full screen. The SDK hides its navigation bar because the chat view draws its own header.

### Retain a conversation across minimize/reopen

Keep an `AgentChatHandle` in the host when the conversation should remain alive while minimized. Reuse that same handle to reopen the conversation:

```swift
@MainActor
final class SupportCoordinator {
    private let handle: AgentChatHandle

    init(configuration: SDKConfiguration) {
        handle = AgentChatUI.initialize(configuration: configuration)
    }

    func open(from viewController: UIViewController) {
        AgentChatUI.show(in: viewController, handle: handle, title: "Support")
    }

    func reopen(from viewController: UIViewController) {
        AgentChatUI.show(in: viewController, handle: handle, title: "Support")
    }
}
```

There are corresponding `AgentChatUI.view(handle:)` and `AgentChatUI.present(from:handle:)` overloads. A retained handle preserves the session, draft text, selected files, form answers, and survey presentation when minimized. The UI's Minimize control is available with a retained handle. `handle.close()` releases the UI resources; `handle.endSession()` explicitly ends the Runtime session. `SessionConfig(endSessionOnClose: true)` makes host-driven `close()` end the session as well.

The configuration-only presentation creates and owns its view model for that presentation. Use a retained handle when the host needs to reopen the same conversation.

## 3. Brand and style the native UI

### Colors and theme

Set base values with `ThemeConfig`. Runtime `WidgetConfig.theme` values, when present, take precedence for the values they provide; the SDK configuration supplies fallbacks.

The native theme resolves these palette roles:

| Theme role | Config / Runtime value |
| --- | --- |
| Accent and primary actions | `primaryColor` |
| Chat background and surface | `backgroundColor`, `surfaceColor` |
| Main and muted text | `textColor`, `textMutedColor` |
| Header | `headerBackgroundColor`, `headerTextColor` |
| User and assistant bubbles | `userBubbleColor`, `userBubbleTextColor`, `assistantBubbleColor`, `assistantBubbleTextColor` |
| Composer | `composeBarBackgroundColor`, `composeBarTextColor`, `composeBarPlaceholderColor` |
| Borders and corners | `borderColor`, `borderRadius`, `messageBubbleRadius` |

The base `ThemeConfig` initializer exposes primary/text/background/surface colors, border radius, font family, and dark-mode default. Runtime theme data can additionally provide the full palette, background image, density (`compact`, `comfortable`, or `spacious`), base font size, and named message-bubble radii (`xs`, `s`, `m`, `l`, `xl`). Only HTTP(S) background image URLs are used.

Control the chat color scheme per presentation with `ChatUIOptions.appearance`:

```swift
let options = ChatUIOptions(appearance: .system) // .light, .dark, or .system
AgentChatUI.view(configuration: configuration, uiOptions: options)
```

The default UI option is `.light`. `.system` follows the host color scheme unless the Runtime supplies an explicit dark-mode preference; `.dark` forces dark appearance.

### Fonts

Pass `ChatFonts` to a chat presentation to choose the regular and monospace font families:

```swift
let fonts = ChatFonts(family: "AvenirNext-Regular", monospaceFamily: "Menlo")
AgentChatUI.view(configuration: configuration, fonts: fonts)
```

Font names must be available to the host app. Runtime theme data can also supply a font family and base font size; the `ChatTheme` passed to a custom header, footer, or template exposes the resolved colors and typography helpers.

### Header and title

Set the built-in header title with the `title` argument. Replace the header with a SwiftUI builder when the app needs its own controls or layout:

```swift
let header: ChatHeaderBuilder = { context in
    AnyView(
        HStack {
            Text(context.title)
            Spacer()
            if !context.statusText.isEmpty {
                Text(context.statusText)
            }
            if context.canMinimize {
                Button("Minimize", action: context.onMinimize)
            }
            Button("Close", action: context.onClose)
        }
        .padding()
    )
}
```

The builder receives the resolved theme, title, connection status text, and close/minimize actions. Only show a minimize control when `context.canMinimize` is true.

The host app owns the iOS status bar. There is no public SDK option to set its background color or style.

### Composer and footer

Replace the composer with a `ChatFooterBuilder`. The provided context keeps the custom composer connected to the SDK's draft, send, and optional attachment actions:

```swift
let footer: ChatFooterBuilder = { context in
    AnyView(
        HStack {
            if let attach = context.onAttach {
                Button("Attach", action: attach).disabled(!context.enabled)
            }
            TextField(context.placeholder, text: context.text)
                .disabled(!context.enabled)
                .onSubmit(context.onSend)
            Button("Send", action: context.onSend)
                .disabled(!context.canSend)
        }
        .padding()
    )
}
```

Use `context.enabled` to disable editing while disconnected, `context.canSend` for the send button, `context.isUploading` to show upload progress, and `context.pendingAttachments` to display ready-to-send files. `onAttach` is optional: it is absent when attachment sending is unavailable, including when session permission is missing or a send is in progress. Keep the binding and callbacks in the custom footer so message text and file uploads continue through the SDK.

The SDK does not expose independent setters for the built-in footer's height, icon arrangement, or padding. Replace the footer builder when the host needs a different layout.

### Localization and text

The SDK localizes its own UI strings using the configured locale and fallback locale. Host overrides can be supplied through `LocalizationConfig.overrides` or `ChatStrings`. The dictionary keys are the English SDK string values; Runtime-authored prompts and message content are not translated by this mechanism.

```swift
let strings = ChatStrings(
    localeIdentifier: "fr",
    fallbackLocaleIdentifier: "en",
    overrides: [
        "Send message": "Envoyer",
        "Reconnect": "Reconnecter",
        "Answered by AI": "Réponse de l’IA",
        "validation.required": "Ce champ est obligatoire."
    ]
)
let options = ChatUIOptions(strings: strings)
AgentChatUI.view(configuration: configuration, uiOptions: options)
```

Alternatively, add `ArtemisChat.strings` or `Localizable.strings` to the host bundle's locale folders, such as `fr.lproj`. The SDK checks host overrides, host-bundle localization, bundled SDK localization, then the configured fallback.

### Message timestamps

Use `MessageTimestampSettings` to choose whether timestamps are shown, their position, visibility, and date/time format:

```swift
let timestamps = MessageTimestampSettings(
    enabled: true,
    visibility: .interaction,
    position: .below,
    timeFormat: .twentyFourHour,
    dateFormat: .namedMonthDayYear
)
let options = ChatUIOptions(timestamps: timestamps)
```

Supported values are:

- Visibility: `.always` or `.interaction`.
- Position: `.above` or `.below`.
- Time: `.locale`, `.twelveHour` (12-hour), or `.twentyFourHour` (24-hour).
- Date: `.locale`, `.monthDayYear`, `.dayMonthYear`, or `.namedMonthDayYear`.
- Custom format: a Foundation `DateFormatter` pattern in `customFormat`.

An explicit `ChatUIOptions.timestamps` value takes precedence over `SDKConfiguration.theme`; configuration theme values take precedence over Runtime widget theme values. If no explicit host setting is supplied, Runtime timestamp enablement, visibility, position, and format are used when available.

### Close confirmation, feedback, and attribution

The close/minimize confirmation appears by default when the bot is connected and the user taps Close. While connecting, after an initial connection failure, or while disconnected, Close navigates away immediately without the popup. Disable the option to close immediately even for connected sessions:

```swift
let options = ChatUIOptions(
    closeOrMinimizePopup: CloseOrMinimizePopupConfiguration(isShow: false)
)
```

Ordinary assistant-message thumbs feedback is opt-in at the UI layer and also respects `FeaturesConfig.enableFeedback`:

```swift
let options = ChatUIOptions(
    enableMessageFeedback: true,
    feedbackCommentMaxLength: 500
)
```

The comment limit is clamped to 1–4,000 characters. Runtime rich-content feedback templates are rendered separately from ordinary message thumbs feedback.

Enable the localized “Answered by AI” attribution with `FeaturesConfig(showAnsweredByAI: true)` or YAML `features.show_answered_by_ai: true`. The attribution is shown for completed assistant responses, not human-agent messages.

## 4. Built-in and custom message templates

The native UI handles Runtime rich content for images, HTML, video, audio, files, lists, KPI cards, tables, charts, forms, progress, feedback, actions, quick replies, channel-fallback previews, and carousel cards. The public constants are available on `RichTemplateTypes`.

Register an app-owned renderer for a custom payload type. A renderer may also use the same type as a built-in renderer to replace its native presentation:

```swift
var registry = RichTemplateRegistry()
registry.register(RichTemplateRenderer(
    type: "order_card",
    matches: { message in
        (message.metadata?["template"]?.value as? String) == "order_card"
            || (message.rawRichContent?["template"] as? String) == "order_card"
    },
    build: { message, context in
        AnyView(
            VStack(alignment: .leading) {
                Text("Order card")
                Button("Confirm") {
                    context.submitAction("confirm-order", "confirmed", nil, message.id)
                }
            }
        )
    }
))
```

Pass the registry to `AgentChatUI.view`, `show`, or `present`:

```swift
AgentChatUI.view(
    configuration: configuration,
    templateRegistry: registry
)
```

A `RichTemplateRenderer` provides a `matches(message)` predicate and a SwiftUI `build(message, context)` closure. `RichTemplateContext` exposes the message, resolved theme, accent color, and action/feedback submission closures. Use `context.submitAction(actionId, value, formData, renderId)` for an action, or the async `performAction` callback when the host needs the acknowledged action path. Custom renderers are responsible for drawing their own layout and accessibility behavior.

## 5. Host APIs

### Chat UI lifecycle

| API | Use |
| --- | --- |
| `AgentChatUI.view(configuration:...)` | Embed the chat view in a SwiftUI hierarchy. |
| `AgentChatUI.show(in:configuration:...)` | Push chat onto a UIKit navigation stack. |
| `AgentChatUI.present(from:configuration:...)` | Present chat modally from UIKit. |
| `AgentChatUI.initialize(configuration:...)` | Create an `AgentChatHandle` for a retained conversation. |
| `AgentChatUI.view(handle:...)` | Embed a retained conversation in SwiftUI. |
| `AgentChatUI.show(in:handle:...)` / `present(from:handle:...)` | Present or reopen the retained conversation in UIKit. |
| `AgentChatHandle.close()` | Release the chat UI resources; session behavior follows `SessionConfig.endSessionOnClose`. |
| `AgentChatHandle.endSession()` | Explicitly end the Runtime session and close the retained UI. |

Presentation methods accept `title`, `fonts`, `headerBuilder`, `footerBuilder`, `templateRegistry`, `uiOptions`, and a typed `ArtemisUiEvent` callback where applicable. The UIKit push method also accepts `hidesBottomBarWhenPushed` and `animated`.

### UI events

Pass `onEvent` when constructing a view or handle, or assign it to `handle.onEvent`. For multiple retained-handle observers, use `addListener` and keep its registration if you need to cancel it. Events are delivered on the main actor as `ArtemisUiEvent`:

```swift
let handle = AgentChatUI.initialize(configuration: configuration)
let eventRegistration = handle.addListener { event in
    switch event {
    case .deepLinkClicked(let url, let title, let messageId):
        print("Deep link tapped:", url, title ?? "", messageId ?? "")
    case .messageSent(let messageId):
        print("Message accepted:", messageId)
    case .connectionChanged(let status, let detail):
        print("Chat connection:", status, detail ?? "")
    default:
        break
    }
}

// When the listener is no longer needed:
eventRegistration.cancel()
```

`ArtemisUiEvent` includes transcript and streaming changes, typing and status, session and connection lifecycle, upload and feedback acknowledgements, agent transfer and auth signals, contact-center call state, deep links, minimize, and close events. For a retained handle, `addListener` supports multiple observers and returns a registration token that can be cancelled.

### Direct transport API

Use `AgentSDK` when the host needs to own connection and messaging outside the stock chat UI. It is main-actor isolated.

```swift
@MainActor
final class ChatService {
    let sdk: AgentSDK

    init() throws {
        sdk = try AgentSDK.initialize(fromBundle: .main)
    }

    func start() async throws {
        try await sdk.connect()
    }

    func send(_ text: String) async throws {
        _ = try await sdk.sendMessage(text)
    }

    func stop() {
        sdk.disconnect()
    }
}
```

The SDK can also be initialized from a file URL, a YAML string, or an explicit `SDKConfiguration` using `AgentSDK.initialize(from:)`, `AgentSDK.initialize(yaml:)`, or `AgentSDK.create(with:)`. `SDKConfigurationLoader` provides corresponding load helpers.

#### Events

Set `sdk.delegate` to an `AgentSDKDelegate` or subscribe to Combine publishers:

- `sdk.sdkEvents`: connection, reconnect, error, idle-timeout, and session-scope events.
- `sdk.chatEvents`: message receive/history, streaming start/chunks/end, typing, activity/thoughts, response cancellation, agent transfer, and chat errors.
- `sdk.contactCenterEvents`: Contact Center call invitations, capabilities, and call lifecycle.

#### Messaging and actions

- `connect()` returns the Runtime session ID; `disconnect()` disconnects; `endSession()` ends the Runtime session; `isConnected()`, `getSessionId()`, and `getWidgetConfig()` read current state.
- `sendMessage(_:metadata:attachmentIds:)` sends text and optional metadata or uploaded attachment IDs, returning a local message ID.
- `submitAction(_:value:formData:renderId:)` submits an interactive action synchronously.
- `performAction(_:value:formData:renderId:displayText:)` submits the action asynchronously through the acknowledged path.
- `getMessages()` returns local history; `refreshHistory()` refreshes persisted history; `clearHistory()` clears local messages.
- `sendUserPresence(isTyping:)` sends typing or stop-typing presence; `recordActivity()` updates session activity.

#### Feedback

Submit Runtime feedback with the optional action render ID and follow-up answer fields:

```swift
let responseId = try await sdk.submitFeedback(
    messageId: serverMessageId,
    ratingType: "star",
    ratingValue: 4,
    feedbackText: "Helpful answer",
    actionRenderId: renderId,
    followUpRating: nil,
    followUpText: nil
)
```

The method requires a connected session and waits for the feedback acknowledgement (10 seconds by default). The UI's ordinary thumbs feedback and rich feedback templates use this transport path. Agent-transfer surveys use the separate `submitAgentTransferSurvey(_:score:comments:)` API.

The current iOS public API does not expose Android's `advancedFeedback` configuration flag, `FeedbackDraft` host submission method, or message-level feedback-response snapshot collection. Do not add `features.enable_advanced_feedback` to the iOS YAML and expect it to enable a feature in this SDK version.

#### Attachments

The UI exposes the native photo, camera, and file pickers when the active session allows attachment writes. Direct host code can upload a file and send the returned ID:

```swift
let attachmentId = try await sdk.uploadAttachment(
    fileURL: fileURL,
    contentType: "application/pdf"
)
_ = try await sdk.sendMessage(
    "Please review this file",
    attachmentIds: [attachmentId]
)
```

Use `resolveAttachmentDownloadURL(attachmentId:)` to resolve a fresh download URL. The built-in picker enforces `AttachmentConfig` file-size and MIME-type rules and the Runtime session's attachment permissions/limits. A host-provided picker should apply the same `AttachmentConfig` policy before upload. The UI supports at most five files on a message.

#### Session data

- `updateCustomData(_:)` merges session-scoped values into subsequent outgoing messages.
- `customData` reads the current snapshot; `clearCustomData()` clears it.
- `getSessionScope()` returns the current Runtime permission/feature scope.
- `dispose()` disconnects, releases resources, and completes the SDK event publishers.

#### Contact Center

When Contact Center is enabled, the host can request fallback SBC details with `requestContactCenterSbcDetails(requestId:)` and send call decisions with `respondToContactCenterCall(_:call:reason:)`. An async response variant is available when the host must wait for the send to finish. Contact Center call events are exposed on `contactCenterEvents`. Enable the feature with `FeaturesConfig(enableContactCenter: true)`; call availability also depends on Runtime session capability and permissions.

## 6. Platform-specific notes

- The SDK uses SwiftUI builders for custom header, footer, and rich-content UI. It does not expose Android View/XML customization hooks.
- The host app owns status-bar appearance and navigation policy. The UIKit push API can hide or retain the tab bar; modal presentation is full screen.
- There is no separate public iOS setter for the assistant avatar, launcher icon, built-in composer metrics, or status-bar color. Use Runtime theme/content where supported, or replace the relevant region with a custom header/footer/template.
- Runtime-authored feedback prompts and labels are preserved. Native rich feedback templates are supported, but the Android advanced-feedback flag and typed host draft/snapshot APIs are not part of the current iOS public surface.
